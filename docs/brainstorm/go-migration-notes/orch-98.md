# Go migration notes — lane orch-98

Append-only. One entry per finding, newest last. Format and numbering follow `docs/brainstorm/go-migration-notes.md`; that file is now history and is not edited after 2026-09-12.

- ~~**Bug 15 — the retry backoff was computed and then ignored**~~ — **RESOLVED** (fix/retry-backoff-honored, 2026-09-12). Found by opus-2 porting the reaper (#143). The retry branch of `_reap_once` resets the task to `todo` and queues a `_RetryItem` stamped `retry_earliest_at = now + backoff`; `_refill` drains the retry queue first and correctly skips items whose time has not come — then its ready-set pass, which knew nothing about the retry queue, found the task in `todo` with its deps done and launched it in the same tick. `retry.backoff_seconds` and `retry.rate_limit_backoff_seconds` delayed nothing, a rate-limited provider was hit again immediately, and the queued item launched the task a second time when its backoff expired. Never caught: `test_rate_limit_failure_uses_long_backoff` asserted the stamp, not the effect. Fix: the ready-set pass skips ids the retry queue still owns; `test_ready_set_does_not_relaunch_a_task_the_retry_queue_still_owns` runs `_refill` with a queue that offers the task again and asserts nothing launches inside the window and exactly one launch after it. Go: `ReadyOpts.Waiting` (#143).

- ~~**Bug 16 — the "sub-agent already finished" guard read tasks.json, which sqlite never touches**~~ — **RESOLVED** (same branch). `scripts/task-finish.sh` → `orch task-status` writes the state backend; under `state.backend: sqlite` (default since v0.11) tasks.json keeps `todo`, so `_task_status_in_file` returned `todo` forever and the false-positive guard in the terminal-failure branch never fired on any project created since. Fix: `_task_status_current` asks the state backend first (`get_task_status`) and falls back to the file for file-backed projects. Go reads the backend (#143).
