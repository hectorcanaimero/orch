# Go migration notes — lane orch-98

Append-only. One entry per finding, newest last. Format and numbering follow `docs/brainstorm/go-migration-notes.md`; that file is now history and is not edited after 2026-09-12.

- ~~**Bug 15 — the retry backoff was computed and then ignored**~~ — **RESOLVED** (fix/retry-backoff-honored, 2026-09-12). Found by opus-2 porting the reaper (#143). The retry branch of `_reap_once` resets the task to `todo` and queues a `_RetryItem` stamped `retry_earliest_at = now + backoff`; `_refill` drains the retry queue first and correctly skips items whose time has not come — then its ready-set pass, which knew nothing about the retry queue, found the task in `todo` with its deps done and launched it in the same tick. `retry.backoff_seconds` and `retry.rate_limit_backoff_seconds` delayed nothing, a rate-limited provider was hit again immediately, and the queued item launched the task a second time when its backoff expired. Never caught: `test_rate_limit_failure_uses_long_backoff` asserted the stamp, not the effect. Fix: the ready-set pass skips ids the retry queue still owns; `test_ready_set_does_not_relaunch_a_task_the_retry_queue_still_owns` runs `_refill` with a queue that offers the task again and asserts nothing launches inside the window and exactly one launch after it. Go: `ReadyOpts.Waiting` (#143).

- ~~**Bug 16 — the "sub-agent already finished" guard read tasks.json, which sqlite never touches**~~ — **RESOLVED** (same branch). `scripts/task-finish.sh` → `orch task-status` writes the state backend; under `state.backend: sqlite` (default since v0.11) tasks.json keeps `todo`, so `_task_status_in_file` returned `todo` forever and the false-positive guard in the terminal-failure branch never fired on any project created since. Fix: `_task_status_current` asks the state backend first (`get_task_status`) and falls back to the file for file-backed projects. Go reads the backend (#143).


- ~~**Bug 20 — `orch run` spins forever on a task whose model has no route**~~ — **RESOLVED** (fix/route-missing-blocks, 2026-09-12). Found by opus-2 porting the run loop (#153): a testscript hung until its 540 s timeout. `_refill`'s ready-set pass looked the route up, logged `route missing at dispatch time`, and `continue`d — the task stayed `todo`, `queue.ready()` returned it on the next tick, and the termination condition ("nothing ready, nothing in flight, no retries") could never hold. Reachable today by deleting a `model_router.yaml` entry a task still references after `validate` ran. Fix: the task is blocked (`call_task_block` with `route missing for model <m>`, a `block` event, `queue.mark_blocked`, `run_file.mark_blocked`), so the row says why and the loop ends. The bug 15 test's stub queue offered the task forever and passed through the silent skip; it now stops once spawned, as the real queue does. Go (#153) distinguishes *waiting* (capacity, budget window, backoff) from *never* (no route, no adapter, no cap) and ends the run naming the tasks.

- ~~**Bug 22 — the stakeholder summary showed spend with `show_spend_to_stakeholder` off**~~ — **RESOLVED** (fix/stakeholder-spend-flag, 2026-09-12). Found by sonnet porting the snapshot (#177). The flag (default false, "spend is sensitive") only added `api_budget_summary` to the stakeholder route allow-list; `/stakeholder/summary` — the payload the stakeholder page renders — carried `spend_rounded_usd`, `spend_by_day` and the spend sentence of `exec_summary` unconditionally. `test_stakeholder_summary_json_shape` asserted the 1.5 with no config at all, so the leak was pinned, not caught. Fix: the flag governs every spend figure in the payload; keys stay for the SPA and read null / empty. Go's snapshot (`Input.ShowSpend`, #177) already gated it.

- ~~**Bug 27 — CI polling never resolved: `gh pr checks` has no `conclusion` field, and `state` is uppercase**~~ — **RESOLVED** (fix/ci-polling-field, 2026-09-12). Found by opus-2 capturing real `gh pr checks` output for the Go port (#211), running down a 30-second suspicion he had flagged during #171 ("both binaries compare lowercase keys"). Two bugs in four lines, the outer hiding the inner: `get_ci_status` asked for `--json state,conclusion`, which gh rejects with exit 1 ("Unknown JSON field"), and the non-zero branch answered `"pending"` — so every PR was pending forever, `ci_max_retries` never tripped, `auto_merge` never fired. With the field fixed, gh emits `state` as `SUCCESS`/`FAILURE`/`NEUTRAL` against lowercase maps, so every lookup would still have missed. The tests fed `{"state": "completed", "conclusion": "success"}`, a shape gh never produces: a fixture written from what the code reads tests the code against itself (third time in this port: bug 24's comment fixtures, `make-goldens.py`'s `dep()`). Fix: ask for `name,state,bucket`, lowercase `state` before the lookup (the map stays lowercase so the Python and Go tables remain comparable; `bucket` is gh's own summary and is deliberately not mapped on), and say on stderr why a gh call failed instead of dressing it as "still waiting". Fixtures: real gh 2.100.0 output in `orchestrator/tests/fixtures/gh/2.100.0/`, never edited. Go: #211.
